# Phase 06.1 Plan 06: Genre Selector UI + Regenerate Gutter Summary

**PluginEditor gains a 26px genre chip row (narrowing the waveform), an exactly-5 FIFO genre selector overlay, and a horizontal regenerate/play/save icon triple per MIDI row, all wired directly onto the 06.1-05 processor API with zero new update paths.**

## Performance

- **Duration:** ~25 min
- **Tasks:** 3/3 completed
- **Files modified:** 16 (7 new, 9 modified)

## Accomplishments

- `MidiRowLayout.h`'s vertical play/save icon pair replaced by a horizontal `regenerateIconRect`/`playIconRect`/`saveIconRect` triple (`kRowWidth = kIconSize*3 + kIconGap*2 = 40`, right-aligned as a group, vertically centred, empty-safe below `kIconSize` height or `kRowWidth+kRightMargin` width) -- proven against the real 92x28 gutter fixture by rewritten `MidiSetsPanelLayoutTests.ThreeIconRowFitsInsideGutterAndDoesNotOverlap`/`ThreeIconRowDegenerateSafe` (Pitfall E closed).
- `MidiRowView` gained `onRegenerateRow(int patternIndex)` and a 5-pip dice-style flat-rect regenerate glyph (no circular-arrow paths); `MidiSetsPanel` forwards the hook into every rebuilt `MidiRowView`, exactly the same idiom as the existing `onAuditionToggle`.
- New `Source/UI/GenreSelectionLogic.h`: header-only pure `toggleMainGenre()` implementing the locked FIFO-swap "exactly 5" interaction model (already-selected click = no-op; new click evicts index 0/oldest, appends at the end/newest). `GenreSelectionLogicTests.ExactlyFiveInvariantHoldsAcrossToggleSequences` proves the invariant (size==5, no duplicates, all ids in-universe) after every one of 50 scripted toggle steps, not just for a single call.
- New `GenreChipsBar`: pure `computeChipRects`/`changeButtonRect` layout functions (equal-width chips, 4px gaps, reserved right zone for the CHANGE button) plus a flat-rect pixel Component -- active chip filled gold (`0xffe8c547`), inactive chips dark with a 1px border, driven by ids/shortLabels the editor pushes in (never reaches into `GenreRegistry` itself).
- New `GenreSelectorOverlay`: full-editor-bounds modal (`RegionSelectorOverlay` category) listing all 10 `allGenres()` with checkbox glyphs (filled gold = selected) + a DONE button; a backdrop click outside the panel also dismisses. Deliberately dumb -- only reports `onGenreToggled(clickedId)`; the editor applies `toggleMainGenre` + `processor.setMainGenres` and calls `setSelection()` back, so the overlay stays open across multiple toggles (no per-click dismiss, matching the locked "лише 5" always-valid UX).
- `PluginEditor::resized()` inserts the 26px chip row between `chordTimeline` and the waveform (narrowing it from ~232px to ~206px; `regionOverlay` bounds stay byte-identical to `waveformView`'s). `genreSelectorOverlay` is declared last among child components and added via `addChildComponent` (hidden by default, full-editor bounds, z-orders on top via `toFront(false)` on open).
- New private `refreshGenreChips()` helper resolves `processor.getMainGenreIds()` -> shortLabels via null-checked `findGenre()` (Pitfall F: unknown ids skipped, never dereferenced), called from the ctor (editor-reopen restore) and the `analysisBroadcaster` branch of `changeListenerCallback` (keeps chips in sync with any processor-side genre change, including a genre-eviction re-activation from `setMainGenres`).
- Per-row regenerate wiring: `midiSetsPanel.onRegenerateRow = [this] (int idx) { processor.regenerateRow (idx); }` -- rides the exact same `analysisBroadcaster` -> `MidiSetsPanel::setRows()` full-rebuild path every other row-set change already uses. No new update mechanism was added (Pitfall D honored, verified: `grep -rn "updateSingleRow|updateRow" Source/` still returns nothing).
- `grep -rn "PopupMenu" Source/UI/Genre*` returns nothing -- the research-flagged anti-pattern (breaks the locked pixel-art identity, fights single-click-dismiss for a multi-toggle UX) was avoided by construction.
- GEN-09/GEN-10/GEN-11 all marked complete in `REQUIREMENTS.md`. GEN-10 was the only remaining gap after 06.1-05 (its state/persistence half was already done; the chip/menu UI itself was this plan's job) -- now fully closed end-to-end.
- Full suite green throughout: 175/175 after Task 3 (170 carried over from 06.1-05 + 5 new: 2 `MidiSetsPanelLayoutTests` rewrites already counted in the base + `GenreSelectionLogicTests` x3 + `GenreChipsBarLayoutTests` x2). `pluginval` strictness 5 SUCCESS on both VST3 and AU against a freshly rebuilt/installed plugin bundle.

## Decisions Made

- Regenerate glyph implemented as a 5-pip dice pattern (flat 2x2 `fillRect` squares) rather than any arrow/path shape, per the research's explicit recommendation and the codebase's flat-rect-only pixel-art constraint.
- `GenreChipsBar::setGenres` takes parallel `ids`/`shortLabels` `StringArray`s (already resolved by the editor) rather than `GenreSpec` pointers, keeping the chip bar decoupled from `GenreRegistry.h` -- matches `MidiRowView`'s "hooks/data pushed in, never reaches into the processor/registry itself" idiom.
- `GenreSelectorOverlay`'s row/panel/done-button rects stayed private (non-static) helper methods rather than standalone pure free functions -- the plan's own test requirements only called for `GenreSelectionLogicTests` and `GenreChipsBarLayoutTests`, not overlay-geometry tests, so no speculative extraction was added.
