## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `PatternArchetype.kind` never explicitly assigned per slot**
- **Found during:** Task 1 test run (RED->GREEN verification)
- **Issue:** All 5 slots were populated via `spec.patterns[(size_t) PatternKind::X]` references, but the archetype's `.kind` field itself was never set — since `PatternKind kind = PatternKind::SustainedChords;` is the struct's default member initializer, every slot after index 0 silently stayed tagged `SustainedChords`. `RegistryShapeIsWellFormed`'s `patterns[i].kind == (PatternKind) i` invariant caught this immediately (24 failed assertions across the `house` genre check alone, and equivalently for the other 4).
- **Fix:** Added an explicit `x.kind = PatternKind::X;` line to every one of the 25 slot-population blocks across all 5 main genre builders (and carried the discipline into all 5 Task 2 builders from the start).
- **Files modified:** `Source/MidiGen/GenreRegistry.cpp`
- **Verification:** `RegistryShapeIsWellFormed` green immediately after; full targeted suite green.
- **Committed in:** `b80a19b` (Task 1 commit)

**2. [Rule 3 - Blocking] `GenreRegistry.cpp` missing `GrooveEngine.h` include**
- **Found during:** Task 1 build (boom-bap's `kSwingLight`-based rhythm pools)
- **Issue:** `GenreRegistry.h` does not transitively expose `GrooveEngine.h`'s swing constants; the build failed with `use of undeclared identifier 'kSwingLight'` the moment boom-bap's swung onsets were authored.
- **Fix:** Added `#include "GrooveEngine.h"` to `GenreRegistry.cpp`.
- **Files modified:** `Source/MidiGen/GenreRegistry.cpp`
- **Verification:** Build succeeded immediately after; full targeted suite green.
- **Committed in:** `b80a19b` (Task 1 commit)

**3. [Rule 3 - Blocking] Catch2 `CHECK_FALSE` macro rejects a raw `&&` expression**
- **Found during:** Task 1 test authoring (`RegistryShapeIsWellFormed`'s BassLine-slot invariant)
- **Issue:** `CHECK_FALSE (p.rhythmPool.empty() && p.bassRhythmPool.empty())` failed to compile — Catch2's expression decomposer explicitly rejects an un-parenthesized `&&`/`||` inside its assertion macros (`static_assert` guard), requiring the expression to be wrapped.
- **Fix:** Wrapped the expression in an extra pair of parentheses: `CHECK_FALSE ((p.rhythmPool.empty() && p.bassRhythmPool.empty()));`.
- **Files modified:** `Tests/GenreRegistryTests.cpp`
- **Verification:** Build succeeded; test compiled and ran correctly.
- **Committed in:** `b80a19b` (Task 1 commit)
