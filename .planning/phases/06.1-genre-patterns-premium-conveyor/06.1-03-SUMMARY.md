# Phase 06.1 Plan 03: PatternEngine (Generic Data-Driven Pattern Engine) Summary

**generatePattern implemented as one generic per-segment loop (tone set -> register/voice-leading -> rhythm tiling -> velocity/accent/jitter -> ornaments) covering all 5 PatternKind slots from declarative PatternArchetype data, replacing Phase 5's four per-style generator functions; harmony preservation proven by construction across 21 seed variations, TDD RED -> GREEN -> REFACTOR.**

## Performance

- **Duration:** ~24 min
- **Tasks:** 2/2 completed (Task 2 included the plan's optional REFACTOR sub-step)
- **Files modified:** 2 (Source/MidiGen/PatternEngine.cpp, Tests/PatternEngineTests.cpp)

## Accomplishments

- `Tests/PatternEngineTests.cpp` populated with all 12 required behaviors against hand-authored `PatternArchetype` fixtures (a file-local `makeArchetype()` helper), fully independent of 06.1-04's `allGenres()` data -- confirmed genuine RED against the 06.1-01 skeleton (every membership-check test guarded with an explicit non-empty assertion so no test could pass vacuously on an all-empty return).
- `generatePattern` implemented: NoChord segments emit zero notes in every slot; tone sets come exclusively from `toneSetIntervals`; register placement is octave-preserving-clamped or voice-led via `VoiceLeadingEngine::nearestOctaveNote`; rhythm comes from seed-selected `rhythmPool` tiled via `tileOnsets`; StabArp distributes one arpeggiated tone per onset (`Arpeggiator::Up`); BassLine delegates to `generateBassRow` then reshapes octave/velocity; TopLineMotif inserts a hash-thresholded diatonic passing tone (the only non-chord-tone path, still key-diatonic).
- Harmony preservation proven across 21 seed variations (`computeBaseSeed` + `combineSeedWithVariation`, counters 0..20): every note in every variation is chord-tone-or-diatonic.
- Determinism proven byte-identical (all four `NoteEvent` fields) for repeated calls with identical inputs.
- Performance budget met: 5 `generatePattern` calls on a 150-segment real-track-scale fixture complete in well under 1ms (min-of-5-runs idiom, matching `MidiRowBuilderTests`' own precedent).
- Optional REFACTOR performed: `generatePattern` hit 153 lines (over the plan's ~150-line guideline); extracted `applyRegister`, `meanPitchOr`, and `emitSegmentOnsets` file-local helpers, bringing the top-level function to ~70 lines with zero behavior change (suite stayed green).
- Full suite green throughout: RED confirmed 12/12 failing against the skeleton; GREEN confirmed 12/12 passing plus the pre-existing 158-test baseline; final full-suite run (after both this plan and the concurrently-running 06.1-04 landed) is 175/175 green.

## Decisions Made

- Octave-preserving register clamp (not truncating `jlimit`) applied to every slot's register placement, not just the voice-led path -- maximum MIDI quality with no correctness trade-off.
- Ornament-roll hash denominator changed to 10000 (from Humanization.h's 9999 idiom) specifically to make `ornamentProbability` 0.0/1.0 exact, deterministic boundary guarantees rather than 1-in-10000 statistical near-certainties.
- `generatePattern` refactored into three file-local helpers once it crossed the plan's ~150-line guideline (153 lines) -- `applyRegister`/`meanPitchOr`/`emitSegmentOnsets`, matching the plan's own suggested decomposition (`buildToneSet`/`applyRegister`/`emitOnsets`).
- GEN-09/GEN-11 left unchecked in REQUIREMENTS.md (see key-decisions above for full rationale) -- this plan proves the engine in isolation; end-to-end evidence needs 06.1-04 + 06.1-05.
