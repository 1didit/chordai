# Phase 06.1 Plan 05: MidiRowBuilder + PluginProcessor Genre Wiring Summary

**PluginProcessor gains a full genre-selection API (setActiveGenre/setMainGenres/regenerateRow(int)) over MidiRowBuilder's new generateGenreRows/regenerateRow, backed by GenreState-persisted apvts.state properties; Phase 5's four fixed per-style generator functions are fully retired with every surviving test behavior migrated.**

## Performance

- **Duration:** ~35 min
- **Tasks:** 3/3 completed
- **Files modified:** 13 (2 new test files, 1 new legacy-generator deletion pair x2, 9 modified)

## Accomplishments

- `MidiRowBuilder::generateGenreRows(result, genre, settings)` builds all 5 slots of one genre at the baseline variant; `regenerateRow(result, genre, patternIndex, variationCounter, settings)` builds one slot at a caller-supplied counter -- both share one `assembleGenreRow()` row-identity helper (`id = "<genreId>-<slug>"`, `label = "<GenreLabel> — <Slot Label>"` via `CharPointer_UTF8`, matching `MidiSetsPanel.cpp`'s own non-ASCII-literal precedent).
- `ChordAIAudioProcessor` gains the full genre API: `setActiveGenre` (full 5-row rebuild over the current `AnalysisResult`, no re-analysis, counters reset, `GenreState::write`, broadcast), `setMainGenres` (defensive validate: size==5, every id resolves, no duplicates; FIFO-eviction re-activates the newest genre), `regenerateRow(int)` (bumps `patternVariationCounters[i]` BEFORE the call -- Pitfall B -- splices into a COPY of the row vector, publishes via the same `atomic_store` + `analysisBroadcaster` path -- Pitfall D), `getActiveGenreId`/`getMainGenreIds`.
- `activeGenreId`/`mainGenreIds` are restored from `GenreState` in both the ctor AND `setStateInformation` (`RegionState` precedent) so an editor-reopen/DAW-reload lands coherent.
- `triggerAnalysis`'s `onDone` now publishes `generateGenreRows(*result, *genre)` in the exact same `atomic_store`-before-`sendChangeMessage()` ordering as before (GEN-01's "same broadcast" guarantee untouched); every `findGenre()` call site is null-checked with a `"trap"` fallback (Pitfall F) -- proven live by `UnknownActiveGenreIdFallsBackSafely`.
- Legacy retirement: `generateAllRows`, `AsIsRowGenerator.h/.cpp`, `StyleVoicingGenerators.h/.cpp` deleted from source and `CMakeLists.txt`. Full test migration mapping: determinism test → `MidiRowBuilderGenreTests.SameInputProducesByteIdenticalRows`; voicing-interval correctness → `ChordToneMapperTests`/`PatternEngineTests`; house-stab data → `GenreRegistryTests`; the EXPLICIT GAP CLOSURE item -- `StyleVoicingTests.RnbVoiceLeadingMinimizesMovement` (the only test proving voice leading MINIMIZES total movement, not merely register-clamps) -- ported verbatim in assertion shape as `PatternEngineTests.VoiceLeadingMinimizesMovementAcrossTransition`, exercising `VoiceLeadingEngine::nearestOctaveNote` through `generatePattern`'s `useVoiceLeading` path. `Tests/StyleVoicingTests.cpp` and `Tests/MidiRowBuilderTests.cpp` deleted.
- `Tests/GenreStateTests.cpp`: ValueTree round-trip through XML, missing-property fallbacks, and corrupt (wrong-token-count) `mainGenreIds` falling back to the caller-supplied default (never a wrong-sized array).
- `Tests/MidiRowBuilderGenreTests.cpp` (6 cases): 5-row shape/identity for a known genre+progression, byte-determinism, NoChord safety across all 5 slots, cross-genre distinctness (trap vs house, >=3/5 slots differ), `regenerateRow`'s counter semantics (counter 0 == baseline, counter 1 differs, same counter reproduces identically), and identity preservation across regeneration.
- `Tests/PluginProcessorGenreTests.cpp` (7 cases, new): `GenreSwitchRegeneratesDistinctRows`, `RegenerateChangesOnlyTargetRow`, `RegenerateIsDeterministicGivenSameCounter` (two-independent-processors shape, extending Phase 5's own precedent), `RegenerateOutOfRangeIndexIsNoOp`, `RegenerateBeforeAnalysisIsNoOp`, `SetMainGenresValidatesAndPersists` (incl. a `getStateInformation`/`setStateInformation` round-trip onto a second processor), `UnknownActiveGenreIdFallsBackSafely`.
- Full suite green throughout: 170/170 after Task 3. `pluginval` strictness 5 SUCCESS on both VST3 and AU against a freshly rebuilt/installed plugin bundle (`ChordAI_VST3`/`ChordAI_AU` targets rebuilt explicitly before validation, not just the test binary).
- GEN-09/GEN-10/GEN-11 all marked complete -- the full processor-level genre-selection, per-row-regenerate, and main-5-persistence behavior described by those requirements is now proven end-to-end by automated tests (06.1-06 only needs to put buttons on it).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Catch2 `CHECK_FALSE` macro rejects a raw `&&` expression**
- **Found during:** Task 1 (`MidiRowBuilderGenreTests.cpp` build)
- **Issue:** `CHECK_FALSE (note.startBeats >= 4.0 && note.startBeats < 8.0)` failed to compile -- Catch2's expression decomposer rejects an un-parenthesized `&&`/`||` inside its assertion macros (same class of issue documented in 06.1-04-SUMMARY.md's deviation #3).
- **Fix:** Wrapped the expression in an extra pair of parentheses.
- **Files modified:** `Tests/MidiRowBuilderGenreTests.cpp`
- **Verification:** Build succeeded; test compiled and ran correctly.
- **Committed in:** `8c85920` (Task 1 commit)

**2. [Rule 3 - Blocking] `Tests/PluginProcessorMidiGenTests.cpp` still called `generateAllRows`**
- **Found during:** Task 2 (`cmake --build build` verification, after deleting `generateAllRows`)
- **Issue:** Two existing tests computed their "expected" row vector via `generateAllRows(*result)` for a deep-equality comparison against the processor's published rows. Once `triggerAnalysis`'s `onDone` was rewired to publish `generateGenreRows` output (still within Task 2), this comparison would assert against the WRONG data even before the function was deleted; deleting it then broke the build entirely.
- **Fix:** Replaced both call sites with `generateGenreRows(*result, *findGenre(proc.getActiveGenreId()))`, added a `findGenre`-null `REQUIRE` guard, and added the `GenreRegistry.h` include.
- **Files modified:** `Tests/PluginProcessorMidiGenTests.cpp`
- **Verification:** Full suite green (170/170) including both of that file's affected tests.
- **Committed in:** `74c695e` (Task 2 commit)

**3. [Rule 1 - Bug] `GenreSwitchRegeneratesDistinctRows`'s broadcast-flag check raced the async `sendChangeMessage()`**
- **Found during:** Task 3 (first `ctest` run for the new integration suite)
- **Issue:** A bare `CHECK (listener.fired)` immediately after `proc.setActiveGenre("house")` failed intermittently-but-actually-always, since `juce::ChangeBroadcaster::sendChangeMessage()` delivers asynchronously on the message thread -- the flag hadn't been set yet by the time the check ran.
- **Fix:** Replaced the bare check with `REQUIRE (pumpUntil ([&] { return listener.fired; }, 5000))`, matching every other broadcast-observing assertion in this codebase's test suite (`PluginProcessorMidiGenTests.cpp`'s own precedent).
- **Files modified:** `Tests/PluginProcessorGenreTests.cpp`
- **Verification:** Test passed on re-run; full 7/7 targeted suite green.
- **Committed in:** `7cac76e` (Task 3 commit)
