# Phase 06.1 Plan 02: Premium Conveyor Rework Summary

**Conveyor belt reworked per the locked UI-01 decision: idle = fully stopped with a persistent pixel "drop song or melody here" invitation; animates only on drag-hover/analysis; premium procedural detail pass adds synced roller rotation, two-tone dithered belt texture, alternating-shade slats, and an arcing/bouncing chunk-fall — all inside the existing logical-frame/30Hz-Timer pipeline, zero new assets or dependencies.**

## Performance

- **Duration:** ~18 min
- **Tasks:** 2/2 completed
- **Files modified:** 2 (`Source/UI/ConveyorBeltComponent.h`, `Source/UI/ConveyorBeltComponent.cpp`)

## Accomplishments

- Belt motion (`beltOffset`) now gated on `dragHover || analyzing`; idle freezes the belt (and, by extension, the new roller-rotation cue) exactly where it stopped.
- 30Hz `repaint()` skipped while fully idle/static (no active drag/analysis and no chunks in flight) — state-change setters still repaint immediately on transition, so there's no perceptible lag entering/leaving idle.
- "drop song or melody here" drawn into the logical low-res frame (dim warm-white, non-gold) whenever idle; disappears the instant the belt starts moving; persists between loads per the locked interpretation.
- Roller rotation cue: two notch pixels + a static axle pixel per roller, angle driven by `beltOffset`/`slatSpacing`, freezing dead when idle.
- Belt band gained two-tone (lighter-top/darker-bottom) shading, a deterministic travelling dither pattern (`(x + beltOffset) % 4 == 0 && y % 3 == 1`), alternating-shade slats with a leading-edge highlight, and a 1px drop-shadow line under the band.
- Falling-chunk stub extended to `{x, y, vx, vy, bounced}`: chunks now carry horizontal velocity off the right roller, gain gravity, bounce once (damped) near the bottom, then fall through and despawn via the existing below-bounds erase.
- Chunks drawn slightly larger (4x2 logical px) with a 1px darker outline row for read.

## Decisions Made

- Idle rule taken literally: `!dragHover && !analyzing` shows the text and freezes the belt unconditionally, including after a song was already loaded — matches the plan's resolved Open Question 3.
- Repaint-skip guard implemented as a direct boolean expression (`active || !chunks.empty()`) rather than adding a separate `frameDirty` member; the plan explicitly allowed either approach, and this keeps the change minimal since every state-changing setter already calls `repaint()` unconditionally on its own.
- Roller rotation notches drawn via a small local lambda shared by both rollers (left/right), keeping the left/right roller code DRY without introducing any new member state.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Fixed falling-chunk coordinate-space mismatch (pre-existing, invisible stub)**
- **Found during:** Task 2 (chunk arc+bounce implementation)
- **Issue:** `triggerChunkFallStub()`/`timerCallback()` computed chunk position/physics in full-component-resolution units (`getWidth()`/`getHeight()`), but `paint()` drew chunks directly into the low-res logical `frame` (1/4 resolution) with no scale conversion — e.g. a chunk spawned at `x = getWidth() - 4` (~796px on an 800px-wide editor) rendered into a ~200px-wide logical frame, placing it entirely outside the visible canvas. The falling-chunk visual was effectively invisible since it was introduced (04-03).
- **Fix:** Kept physics in the plan's specified full-resolution units (matches the plan's own `getHeight() * 0.92f` bounce-threshold formula and the pre-existing spawn point), and divided position by `pixelScale` only at the `paint()` draw call, so chunks now land correctly in the logical frame's coordinate space.
- **Files modified:** `Source/UI/ConveyorBeltComponent.cpp` (draw call only; physics formulas unchanged from the plan's literal spec)
- **Verification:** Build green; pluginval strictness 5 SUCCESS (Editor Automation pass exercises `paint()`); final visual read deferred to the 06.1-07 human checkpoint by design (same as all UI-01 visual judgment).
- **Committed in:** `3c1554f` (Task 2 commit)
