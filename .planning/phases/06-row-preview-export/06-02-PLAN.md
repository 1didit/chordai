<objective>
Build the PRV-01 audition engine: a deterministic message-thread renderer (`Source/Audio/AuditionVoice` + `AuditionRenderer`) that pre-renders a `MidiSetRow` to PCM, and a lock-free double-buffer handoff into `ChordAIAudioProcessor::processBlock` (preallocated raw buffers + `std::atomic<int>/<bool>` indices). The audio thread only ever does a bounds-checked sample copy.

CRITICAL RT-safety constraint (06-RESEARCH.md Pitfall 2, NEW project finding): this codebase's existing `std::atomic_load`/`atomic_store` shared_ptr publication idiom (`loadedAudio`/`analysisResult`/`midiSetRows`) is FORBIDDEN on the audio thread — those free functions are not lock-free and commonly take an internal mutex/spinlock on the shared_ptr control block. Every existing use is message-thread-to-message-thread; this plan is the first code to reach into `processBlock`, and it must use the plain-atomics double-buffer instead.

Purpose: PRV-01's engine half — UI play/stop wiring lands in 06-03; this plan makes the processor able to play any row safely.
Output: `Source/Audio/` module, processor audition API, `[auditionrenderer]`/`[processoraudition]` tests green, pluginval strictness 5 green (processBlock touched — RT gate mandatory this wave).
