    Animation (all discretionary specifics chosen here as defaults — adjust freely if visually poor, but keep the mechanism):
    - `startTimerHz (30)` in ctor; `timerCallback()` advances `beltOffset = (beltOffset + 1) % slatSpacing` and calls `repaint()` — this component's bounds only, never getParentComponent()->repaint().
    - `paint(Graphics&)`: render into a small logical-resolution `juce::Image` (ARGB, width = getWidth()/4, height = getHeight()/4, i.e. 4x pixel scale) each frame: dark industrial background (e.g. 0xff16161e); a horizontal belt surface band across the middle ~60% of the strip (e.g. 0xff3a3a4a) with darker tread slats (0xff23232e, 2 logical px wide) every `slatSpacing = 8` logical px, drawn at x-positions shifted by +beltOffset so the pattern visibly travels LEFT→RIGHT; two lighter roller circles (0xff5a5a6e) at the far left and right ends; 1-px top/bottom edge highlights for depth. Then blit: `g.setImageResamplingQuality (juce::Graphics::lowResamplingQuality); g.drawImageWithin (frame, 0, 0, getWidth(), getHeight(), juce::RectanglePlacement::stretchToFit);` — the low-res render + nearest-neighbour upscale IS the pixel-art look.
    - Cache nothing across frames beyond beltOffset (the logical image is cheap: ~200x30 px); allocate the Image once in resized() and reuse it (clear each frame) to avoid per-frame allocation churn.
    - RT-safety note in header comment: this class lives entirely on the message thread; it must never be referenced from processBlock.
